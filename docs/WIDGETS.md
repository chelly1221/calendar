# Android 홈 화면 위젯

달력 0.2.0부터 지원합니다. 설치한 Android 앱의 기능이며 웹/PWA의 홈 화면 바로가기와 별개입니다.

## 추가와 사용

1. APK를 업데이트하고 달력 앱에서 한 번 동기화합니다.
2. **앱 설정 → 홈 화면 위젯 → 위젯 추가**에서 설정 후 홈 화면에 추가합니다. 런처가 앱에서 추가하는 기능을 지원하지 않으면, 홈 화면의 빈 곳을 길게 눌러 **위젯 → 달력 → 일정 달력**을 선택합니다.
3. 기본 크기는 4×5칸입니다. 런처가 허용하는 범위에서 가장자리를 늘려 화면을 넓게 채울 수 있습니다.
4. 이전/다음 달과 오늘 버튼으로 앱을 열지 않고 월을 이동합니다. 날짜를 누르면 앱에서 해당 날짜의 일정을 봅니다. 아래 동기화 상태를 누르면 앱을 열어 동기화합니다.
5. 오른쪽 위 설정은 해당 위젯만 바꿉니다. 여러 위젯을 놓고 서로 다른 캘린더·색상·글자 크기를 사용할 수 있습니다. **설정 저장** 전에는 홈 화면이 바뀌지 않으며 닫기·시스템 뒤로 가기는 취소합니다.

## 설정

| 항목 | 선택과 기본값 |
| --- | --- |
| 표시할 캘린더 | 기본 모든 캘린더. 새 캘린더도 자동 포함하거나 직접 여러 개 선택. 앱 화면의 숨김 설정과 독립적 |
| 일정 종류 | 종일·시간 일정 각각 켜기/끄기. 기본 모두 표시, 종일 일정 먼저 |
| 시작 시간 | 제목 앞에 `09:00` 표시, 기본 끔. 여러 날에 걸친 시간 일정은 시작일에만 시간 표시 |
| 글자 크기 | 일정 8~16sp(기본 11), 날짜 10~20sp(기본 12). 시스템 글자 확대 반영 |
| 하루 일정 개수 | 높이에 맞춰 자동 또는 최대 1~8개. 자동 모드는 공간에 따라 최대 16줄, `+N`도 한 줄 사용 |
| 긴 제목과 넘침 | 제목은 한 줄 말줄임. 남는 일정은 `+N`; 한 줄만 들어가면 날짜 옆에 개수 표시. 개수 표시 끄기 가능 |
| 한 주 시작 | 일요일(기본)·월요일·토요일 |
| 주 수 | 해당 월에 맞춰 4~6주(기본), 항상 6주 선택 가능 |
| 날짜 표현 | 앞뒤 달 날짜, 주말 색상, 오늘 강조, 구분선 각각 설정 |
| 바깥 여백 | 0~10dp, 기본 3dp |
| 테마 | 노트와 같은 어두운 테마(기본)·밝게·시스템 |
| 일정 색상 | 캘린더 색을 은은하게(기본)·진하게·글자만 |
| 배경 | 불투명도 0~100%, 둥근/조금 둥근/직각 모서리, 사용자 배경색과 오늘 강조색 |
| 날짜 터치 | 해당 날짜 일정 보기(기본) 또는 새 일정 작성 |
| 다른 달 유지 | 15분(기본)·1시간·직접 오늘을 누를 때까지. 만료 후 다음 위젯 갱신 때 이번 달로 복귀 |
| 동기화 상태 | 마지막 동기화 시각, 미전송 일정 수, 일부 일정 오류 안내. 일반 상태는 숨길 수 있음 |

미리보기는 홈 화면과 같은 렌더러를 사용합니다. 글자를 키우면 미리보기 높이도 늘려 제목을 확인할 수 있게 합니다. 낮은 화면에서는 미리보기도 함께 스크롤됩니다. 실제 런처 크기에서는 표시되는 줄 수가 달라집니다.

## 일정 반영과 보관

- 앱에서 저장·수정·삭제하거나 서버와 동기화하면, 기기 저장소 변경을 감지해 위젯 내용을 갱신합니다. 서버 전송을 기다리지 않아 오프라인 편집도 표시합니다.
- 앱이 닫힌 동안에는 마지막으로 저장된 일정을 표시합니다. 위젯이 별도 Tailscale 세션을 열거나 서버를 백그라운드 조회하지 않습니다. 서버의 새 일정은 앱을 열어 동기화해야 합니다.
- 날짜·시간대 변경, 재부팅, 앱 업데이트 및 Android 주기 갱신 시 다시 그립니다. 주기 갱신은 최소 30분 간격이며 시스템 절전 정책에 따라 늦어질 수 있습니다.
- 현재 월 기준 앞뒤 2년, 총 49개월의 반복 발생 일정을 기기에 보관합니다. 그 밖의 월은 앱에서 확인하라는 문구를 표시합니다. 앱을 다시 열면 보관 기간을 갱신합니다.
- 반복 예외·취소, 종일 일정의 배타적 종료일, 여러 날 일정, 기기 시간대와 floating 시간을 반영합니다. 일정 자체를 위젯에서 수정하지 않으며 날짜 터치로 앱의 기존 편집 기능을 사용합니다.
- 스냅샷은 앱 전용 내부 파일에 원자적으로 저장합니다. 저장에 실패하면 이전 내용을 보존합니다. 기기의 기본 캘린더 읽기 권한이나 서버/NAS 비밀번호를 추가로 요구하지 않습니다.
- 앱의 49개월 스냅샷은 최대 40,000개 발생 일정·16MB입니다. 변환할 수 없거나 용량을 넘는 리소스는 원본을 보존하고 위젯에 일부 일정 확인 안내를 표시합니다.

## 검증

- 실제 Android 16 에뮬레이터의 `AppWidgetHost`에 위젯을 바인딩해 확인했습니다. 개발 전용 호스트와 예시 일정은 release APK에 포함되지 않습니다.
- 전화기 1080×2400, 작은 위젯, 글자 배율 1.3, 태블릿 1600×2400/density240에서 밝은/어두운 위젯 및 설정 화면을 캡처했습니다. 한 줄 일정이 날짜 칸 아래로 잘리지 않는지 자동 검사합니다.
- 기본 앱의 번들 JavaScript → Capacitor → 네이티브 파일 발행, 위젯 월 이동, 설정 저장·취소, 기본값과 개별 설정 분리, 이전 스냅샷 거부를 네이티브 테스트로 확인했습니다.
- Vitest에서 IndexedDB 저장·삭제 후 발행, 앱 복귀 갱신·날짜 이동 전달, 반복 예외·삭제·floating 시간 보존을 확인합니다.
- 실제 홈 런처별 배치, 물리 기기의 제스처·배터리 소모는 에뮬레이터 검증 범위에 포함되지 않습니다.

개발용 전용 에뮬레이터에 debug와 androidTest APK를 설치하고, 해당 에뮬레이터에서만 `appwidget grantbind --package kr.threechan.calendar.debug --user 0`을 허용한 뒤 `kr.threechan.calendar.debug.test/androidx.test.runner.AndroidJUnitRunner`를 실행합니다. 운영 기기의 앱 데이터로 이 테스트를 실행하지 마세요.
