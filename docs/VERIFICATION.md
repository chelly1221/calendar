# 검증 기록

2026-09-11, 달력 0.2.2. 이전 버전 검증도 아래에 보존한다.

## 0.2.2 · 일정 클릭과 색상

- 일정마다 캘린더/리소스 키·반복 회차를 포함한 별도 PendingIntent를 연결했다. `+N`은 날짜 목록으로 연결하며 날짜 터치의 새 일정 설정과 구분한다. 콜드 실행과 열린 앱 모두 로컬 저장소에서 정확한 일정을 연다. 삭제되거나 변경된 스냅샷 대상은 안내하고 다른 일정을 임의로 열지 않는다.
- 개별 VEVENT COLOR → 반복 원본 COLOR → 소속 캘린더 색상 순으로 적용한다. CSS 색상 이름과 HEX를 정규화하며 앱과 위젯에 동일하게 전달한다. tint/solid/plain 모두 1dp 원색 표시선을 유지한다.
- Vitest 37개, TypeScript·웹·서버·Android 서명 빌드 통과. Android 16에서 오프라인 콜드 일정 열기와 실제 RemoteViews 행을 누른 웜 실행 1개, 위젯 통합 5개, 밝은 전화기·글자 1.3 태블릿 캡처 2개를 통과했다. 통합 검사는 키/회차별 PendingIntent 구분과 6가지 테마·일정 스타일 조합의 실제 색상을 확인한다.
- 전화기 1080×2400의 어두운/밝은 테마와 태블릿 1600×2400/density240/font1.3을 확인했다. 첫 에뮬레이터가 종료돼 계측 결과를 내지 못했고 Vulkan을 끈 별도 에뮬레이터에서 위 검사를 완료했다. 물리 기기의 개별 런처 터치 정확도는 확인하지 않았다.
- 기존 서명 인증서와 동일한 versionCode 4 / versionName 0.2.2. APK SHA-256: `677888cf16e82de336be5adf534bda149dded8c6b845f27a0fd33c0b7043faba`.
- 독립 마감 검토가 이번 확장 범위에서 `ship`으로 판정했고 추가 수정 사항은 없었다. [디자인 비교와 캡처 출처](../.impeccable/review/widget-tap-documentation.md)를 기록했다.
- 운영 웹·API 0.2.2 배포 후 health 200, 기존 일정 855개, 공개 API 404를 확인했다. HTML·서비스 워커·favicon과 다운로드 APK의 바이트가 로컬 빌드와 일치한다. 기존 Radicale 자료는 변경하지 않았다.

## 0.2.1 · 저장된 달력 먼저 열기

- 기존 IndexedDB의 유효한 프로필을 읽으면 로컬 달력을 즉시 열고 Tailscale 인증·서버 확인·동기화는 뒤에서 진행한다. 첫 실행과 직접 로그아웃한 상태는 인증 화면을 유지한다. 설정에서 재인증·연결 재시도를 할 수 있다.
- Vitest 34개, TypeScript 검사, 웹·서버 빌드와 서명 Android 릴리스 빌드를 통과했다. 새 회귀 검사는 로컬 프로필 복원, 로그아웃 후 재입장 차단, 잘못된 프로필 처리를 확인한다.
- 별도의 Android 16 에뮬레이터에서 `OfflineStartupTest` 1개 통과. Wi-Fi·모바일 데이터와 WebView 네트워크를 차단하고 합성 일정을 IndexedDB에 저장한 뒤 Activity를 닫고 다시 열었다. 오프라인 상태에서 일정 제목이 보이고 인증 화면이 없음을 확인했다. 테스트는 운영 계정·서버 자료를 사용하지 않는다.
- 기존 서명과 동일한 인증서, versionCode 3 / versionName 0.2.1을 확인했다. APK SHA-256: `1091e9bad10004f8fa49025ba0f065299d82605f77985ece47dd653cd4c3e219`.
- 운영 웹·API를 0.2.1로 배포했다. Tailscale API의 기존 일정 855개, health 200, 공개 데이터 API 404를 확인했다. 웹 HTML·서비스 워커·favicon과 내려받은 APK가 로컬 빌드의 바이트와 일치한다. Radicale 컨테이너와 저장 자료는 재생성하지 않았다.
- 앱 데이터 삭제·앱 제거는 로컬 저장소도 지운다. 이미 받은 일정의 오프라인 재실행을 검증했으며 실제 휴대폰의 기기 재인증 전체 흐름을 새로 실행한 것은 아니다.

## Android 홈 화면 위젯 0.2.0

- 기본 4×5 월간 위젯과 개별 설정, 한 줄 제목·넘침 개수, 실제 글꼴 높이에 따른 표시 줄 수 계산을 구현했다. 네이티브 설정 미리보기와 홈 화면이 같은 렌더러를 사용한다.
- Vitest 33개, TypeScript strict, 웹/서버 빌드 통과. 최종 브리지 오류 처리 변경 후 관련 2개 테스트도 통과했다.
- Android 16 실제 에뮬레이터에서 네이티브 4개 테스트 통과: 런처와 같은 AppWidgetHost 바인딩, 일정 행 잘림 검사, 월 이동, 설정 저장·취소와 기본 설정 분리, 원자적 스냅샷, 실제 번들 JavaScript의 Capacitor 발행 경로를 확인했다.
- 전화기 1080×2400, 작은 위젯, 글자 배율 1.3, 태블릿 1600×2400/density240의 7개 화면을 검토했다. 별도 최종 검토에서 자동 표시 개수와 큰 글자 미리보기의 두 보완 사항이 해결된 것으로 판정됐다. 자동 모드에서 태블릿의 하루 10개 일정이 전부 표시된다. 실물 기기의 개별 런처·제스처·배터리는 검증하지 않았다.
- 이전 Nextcloud 원본 855개를 위젯 스냅샷으로 변환했다. 49개월 발생 일정 1,618개, 2026년 9월 38개, 변환 실패 0개, 약 563KB였다. 원본 일정 내용은 테스트 산출물이나 Git에 추가하지 않았다.
- 원래 서명 인증서로 versionCode 2/versionName 0.2.0 APK를 만들었고, 에뮬레이터에서 서명된 0.1.0 → 0.2.0 업데이트 설치가 성공했다. release 권한·매니페스트에는 개발용 위젯 호스트와 BIND_APPWIDGET 권한이 없다.
- 운영의 API·웹은 `calendar:0.2.0`으로 갱신했다. API health 정상, 기존 855개 리소스·7개 캘린더 유지, 공개 `/api/events` 404, 웹의 새 APK 링크를 확인했다. 다운로드한 APK와 로컬 서명 APK의 SHA-256가 일치했다: `440a24d9a222d7ededa4d8bbad7ad3728e755cf525cf3520565b87a43e4e0115`.
- 닫힌 앱의 위젯은 마지막 로컬 일정을 사용한다. 서버 조회는 앱의 기존 내장 Tailscale 연결과 동기화 수명 주기를 따른다. [위젯 안내](WIDGETS.md), [화면 검토 및 디자인 문서 기록](../.impeccable/review/documentation.md).

## Nextcloud 데이터 이전

- 원본 캘린더 6개(빈 자동 생일 캘린더 포함), 일정 리소스 855개와 반복 예외 7개를 가져왔다. 반복 규칙 34개·VALARM 1개·사용자 정의 속성·일정 시간대를 보존했고, 캘린더 이름·색상 및 기본 `Asia/Seoul` 시간대 5개도 적용했다.
- 추출 전후 sync token 검사 및 별도 재추출의 모든 원본 바이트·SHA-256·메타데이터 비교로 Nextcloud 원본이 변경되지 않았음을 확인했다.
- vobject가 Apple 위치 URI의 경도를 버리는 문제를 발견해 URI 속성 등록으로 수정했다. 원본 855개 전체를 Radicale과 같은 parser·정규화 과정으로 왕복 검사했고, 실제 서버 GET 내용의 전체 캘린더 속성·하위 컴포넌트가 원본과 일치했다. 정규화 차이는 속성 순서·줄 접기·floating-time 내부 표식만 허용했다.
- 실제 Tailscale API와 앱의 `synchronize`를 사용한 독립 IndexedDB에 전체 855개를 내려받았다. 충돌·미전송 0개, 2026년 9월 발생 일정 38개가 원본 확장 결과와 같았다. 운영 데이터에는 검사용 쓰기를 하지 않았다.
- NAS 백업을 임시 복원한 뒤 855개 파일 SHA-256를 API 검증 보고서와 대조하고, 캘린더 속성도 원본과 비교했다. 별도 컨테이너의 `radicale --verify-storage`가 통과했다. 추출 원본·재추출·보고서는 NAS `imports/`에도 체크섬 검증 후 별도 보관했다.
- 전체 Vitest 28개와 TypeScript 검사 통과. 실제 Radicale Docker 이미지에서 위치 URI의 연속 저장 보존 회귀 검사도 통과했다. 가져오기 재개는 이미 존재하는 항목을 읽어 비교하고 건너뛰며, 충돌한 기존 항목은 덮어쓰지 않는다.
- 이번 검사는 서버·동기화 코드에 대한 것이다. 열린 웹 탭은 로그인 대기 상태로 확인했으며, 해당 브라우저는 첫 Tailscale 로그인 후 가져온 데이터를 동기화한다. Android 실물 실행은 추가로 검증하지 않았다.

## 자동 검증

- TypeScript strict 검사, 웹 프로덕션 빌드, 서버 번들 빌드 통과.
- 단위·통합 테스트 24개 통과: Unicode/ICS 왕복, 종일 DTEND, 반복·단일 회차 삭제, 표시 기간 밖에서 이동한 예외, 가져온 사용자 속성·DST 시간대 보존, 충돌 사본 UID, 서로 다른 캘린더의 동일 UID ZIP 내보내기, API 재시작 시 기존 캘린더 확인 및 재사용.
- IndexedDB 오프라인 생성·수정·삭제, 두 기기의 동시 수정, 전송 중 추가 편집, PUT 응답 유실 후 중복 방지, 삭제/수정 충돌, 목록 실패 시 로컬 보존, 중복 UID 가져오기 통과.
- API 허용 계정 검사, 공개 origin 차단, 무조건 DAV 쓰기 및 다른 principal 접근 차단, 잘못된 ICS 거부 통과.

## 운영 환경

- Docker `calendar-api`, `calendar-web`, `calendar-radicale` 실행 및 health 확인.
- HTTPS 웹, favicon/PWA/Android 아이콘·다운로드, 공개 `/api/events`의 404 확인.
- 실제 OS Tailscale 연결로 서버 사용자 인증, CalDAV PROPFIND/GET, 두 개의 독립 IndexedDB 클라이언트에서 생성·읽기·수정·충돌 보존·삭제 검증 (`npx tsx scripts/verify-live.ts`). 테스트가 만든 UUID만 정리한다.
- NAS SMB 3.1.1 암호화 마운트, 매일 백업 타이머, 성공 백업의 SHA-256와 archive 읽기, 임시 디렉터리 복원 후 네트워크가 없는 Radicale 컨테이너의 `--verify-storage` 확인. `--backup` 통합 검사에서 검증용 일정 UID가 실제 복원 파일에 들어 있는지도 비교했다. 운영의 검증용 일정은 이후 삭제했다.

## 화면과 Android

- note의 현재 웹·스타일을 기준으로 데스크톱 1280px와 모바일 390px에서 확인. 개발 전용 별도 저장소의 예시 일정으로 월간 화면과 반복 일정 작성·저장을 확인했다.
- 모바일 날짜 입력이 잘리던 문제를 한 열 배치로 수정했다. 디자인 검사 도구의 자동 탐지 결과는 빈 배열이었다.
- Android release APK 서명·빌드 완료. 앱 패키지, 이름, 기본·적응형 아이콘, 시작 화면이 달력 전용이다. 실행 파일에 Go/WASM과 로컬 폰트를 포함한다.
- 프로덕션 WASM이 시작해 공식 Tailscale 인증 URL을 발급하는 단계와 브라우저 오류 없음까지 확인했다. 실제 새 브라우저/Android 기기의 Tailscale 승인 완료 후 내장 연결 전체 경로와 실물 Android 조작은 사용자 첫 실행에서 확인해야 한다. OS Tailscale을 통한 서버 테스트는 내장 WASM의 인증 완료 검증과 구분한다.
